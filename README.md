# 설계해요 · seolgyehaeyo

**좋은 설계사무소를 고르고, 맡긴 일이 끝까지 잘 진행되도록.**

설계해요는 설계 업무를 맡기는 **의뢰자**를 위한 웹앱입니다. 사무소 선정부터 견적·계약, 설계·인허가, 공사 중 변경과 마지막 자료 인수까지 자신의 프로젝트에서 이어서 기록합니다. 지금 할 일 1~3개와 그대로 물어볼 수 있는 질문을 보여 주고, 약속한 업무·비용·일정·결과물을 다시 찾아볼 수 있도록 돕습니다.

서비스는 **해요(haeyo)** 계열에 속합니다. 한눈(hannun)이 정보 파악과 비교에 중심을 둔다면, 해요는 사용자의 선택·실행·진행·완료를 돕습니다. [이름과 제품 관점](docs/BRAND.md)에 기존 명명 기준과 결정 기록을 보존했습니다.

## 현재 상태 · v0.1

v0.1의 화면, API, 서버 저장과 파일 보관 코드를 구현했습니다. **운영 배포와 종합 검증은 별도 절차**이며, 아래 구현 목록을 운영 검증 완료로 해석하지 않습니다.

- 배포 완료 후 접속 주소: https://seolgyehaeyo.softm.chatgpt.site
- 배포 상태: 배포 전 — 성공 결과를 확인한 후 갱신합니다.
- 기본 공개 범위: 소유자 전용(owner-private).
- 가상 예시는 `/demo`에 분리되어 있으며 읽기 전용입니다. 예시의 업체·금액은 실제 업체 확인 결과나 시세가 아닙니다.

2026-10-22 로컬 HTTP·D1·R2 환경의 API 검사항목 105개가 통과했습니다. 중단된 업로드의 15분 경과 조건에서 보관 상태를 복구하는 경로도 별도로 확인했습니다. 후속 변경을 반영한 최종 TypeScript 검사와 공식 Sites helper의 production build도 통과했습니다. 이 결과는 운영 배포, 실제 ChatGPT 인증이나 다른 기기에서의 이용 검증과 구분합니다.

## 지금 내 상황에서 시작하기

프로젝트 이름, 맡길 일, 현재 단계 **세 가지**로 시작합니다. 지역·주소·예산·목표일은 나중에 채울 수 있습니다. 맡길 일이 분명하지 않으면 “아직 모르겠어요”를 고르면 됩니다.

현재 단계는 준비 → 사무소 선정 → 계약 → 설계 → 인허가 → 공사·변경 → 마무리의 일곱 단계입니다. 이미 진행 중인 단계에서 시작하거나 직접 바꿀 수 있습니다. 단계 선택과 할 일 체크는 관청의 승인, 상대방의 합의 또는 계약 완료를 자동으로 뜻하지 않습니다.

## 구현한 기능

| 기능 | v0.1에서 할 수 있는 일 |
|---|---|
| 내 프로젝트 | 여러 프로젝트 만들기, 기본정보·단계 수정, 서버에서 다시 불러오기, 진행·보관 목록 구분 |
| 사무소 비교 | 후보 이름, 실제 책임 담당자, 경험, 업무 범위, 연락 방식과 선택한 후보 기록 |
| 등록 확인 안내 | 공식 링크 열기, 요청한 자료·확인 내용·출처·확인일 기록 |
| 견적 비교 | 설계·인허가·측량·감리·현장방문·추가변경의 포함·별도·미정·제외와 부가세 구분 |
| 계약·지급 | 계약 상대·범위·결과물·지급·변경·인계 조건과 지급 예정·청구·지급 사실 기록 |
| 진행·질문 | 단계별 할 일, 담당자, 기한, 파일명·받은 자료·접수번호·답변을 텍스트로 기록 |
| 변경 | 변경 전후, 비용 증감, 일정 증감, 상대방과 합의한 자료 기록 |
| 마무리 | 행정 결과, 자료 인수·정산, 남은 작업·보수를 나누어 확인 |
| 자료함 | 파일 원본 또는 가린 사본 업로드, 종류·버전 메모, 이름 검색, 원본 다운로드 |
| 내보내기·삭제 | 기록·이력·파일 목록의 JSON 내보내기, 프로젝트 보관, 프로젝트와 첨부 원본 영구 삭제 |

견적의 미정 금액은 0원과 구분합니다. 견적 총액에 별도 비용을 자동 합산하지 않으며, 지급액 합계에는 금액을 입력한 지급 사실 기록만 포함합니다. 미정 지급 건수는 별도로 표시합니다.

파일당 최대 크기는 20MiB(화면 표기 20MB)입니다. PDF, JPG·PNG·GIF·WebP·BMP·TIFF·AVIF·HEIC·HEIF 사진, DOCX, XLSX, DWG, DXF, UTF-8 TXT를 지원합니다. 새 버전도 별도 파일로 보관합니다. **JSON 내보내기에는 파일 바이트가 포함되지 않으므로 원본은 자료함에서 따로 내려받아야 합니다.**

할 일·질문·변경의 근거는 파일명·받은 자료·답변을 텍스트로 기록하고 원본은 자료함에 별도로 보관합니다. 특정 문서와 해당 기록을 자동으로 연결하는 기능은 없습니다.

## 제품 원칙

1. 전문용어보다 지금 물어볼 질문과 할 일을 먼저 보여 줍니다.
2. 모르는 비용·날짜는 미정으로 남기고, 처음부터 모든 자료를 요구하지 않습니다.
3. 사용자의 확인 기록, 상대방의 합의 자료, 관청의 결과문서를 구분합니다.
4. 등록자료 검색이나 업로드를 자격 검증 완료로 표시하지 않습니다. 미검색을 무등록으로 단정하거나 사기 점수·안전 점수를 만들지 않습니다.
5. 설계·측량·감리·시공의 담당과 계약 범위를 구분합니다.
6. 서버 응답에 따라 저장 중·성공·실패를 표시하며, 수정 충돌 시 입력을 복사하고 최신 기록과 대조하도록 안내합니다.
7. 프로젝트·이력은 D1, 업로드한 파일 내용은 R2에 보관하고 모든 프로젝트·파일 API에서 소유자를 확인합니다.

현재 초대·공동 편집, 공공자료 자동 자격 검증, 전자서명, 실제 송금·결제, OCR·AI 문서 분석, 자동 알림은 제공하지 않습니다. 질문은 복사한 뒤 사용자가 직접 전달합니다. 업로드한 문서를 외부 AI 분석 서비스로 보내는 기능도 없습니다.

## 기술과 개발 실행

| 영역 | 구성 |
|---|---|
| 화면·서버 프레임워크 | Vinext, React, TypeScript |
| 서버 실행 | Cloudflare Workers / Sites |
| 데이터 | Cloudflare D1, Drizzle 스키마·SQL 마이그레이션 |
| 첨부 파일 | Cloudflare R2 |
| 로그인 | Sites의 Sign in with ChatGPT |
| 접근 범위 | Site 소유자 전용 및 API의 사용자별 소유권 검사 |
| 패키지 관리 | pnpm 11.25.0, `pnpm-lock.yaml` |

현재 설치 스크립트는 Bash·flock·GNU timeout을 쓰는 관리형 Linux 환경을 기준으로 합니다. Node.js 요구사항은 `package.json`의 `>=22.13.0`입니다. Sites 환경에서는 공식 helper가 실행 환경과 설치를 관리합니다.

```sh
pnpm install:ci
pnpm dev
pnpm build
```

의존성 설치를 중복 실행하지 않습니다. 서버 DB를 사용하는 로컬 실행에는 SQL 마이그레이션 적용도 필요합니다. 실행 환경, ChatGPT 인증, 로컬 DB 초기화, 실제 배포 절차는 [개발·배포 안내](docs/DEPLOYMENT.md)를 참고하세요. `pnpm dev`의 로컬 미리보기와 `pnpm build` 성공은 운영 배포 완료를 뜻하지 않습니다.
