# 공식 명부 확인 구현 v1

## 실제 기능
- `public/registry.html`: 이름·주소·대표자 부분검색, 등록번호 정확검색, 지역/업종 필터, 12개 단위 페이지 이동.
- 원문 링크·기준일·제공기관·원본 행·SHA-256과 함께 공개명부 수록 사실을 표시한다.
- 등록증과 비교: 이름·등록번호·업종·등록기관·주소. 입력은 브라우저 메모리에서만 사용하고 전송·저장하지 않는다.
- 일부 일치와 식별정보(번호+업종+기관) 일치를 구분한다. 유사 상호는 동일 업체로 확정하지 않는다.
- 등록기관이 없을 때 제공기관을 대신 넣지 않는다. 원자료가 제공하지 않는 등록번호도 만들지 않는다.
- `public/data-status.html`: 수집 주기, 마지막 성공을 강조하고, 시도/성공/원자료 기준일/오류/건수를 별도 표시한다.
- 앱 공통 레이아웃의 '등록업체 확인' 링크로 연결한다. 로그인 기반 프로젝트·파일 API는 변경하지 않는다.

## 수집과 범위
`config/registry-sources.json`에 등록된 4개 공공데이터포털 출처만 다운로드한다. 원문 JSON-LD의 contentUrl을 찾아 연결한다. 이용허락범위 제한 없음이 확인되지 않으면 배포를 중단한다.

UTF-8/CP949 CSV와 XLSX를 지원한다. 구형 바이너리 XLS·수식이 있는 XLSX는 자동처리하지 않고 검토 대상으로 남긴다. 최초 공백/제목행, 누락된 셀, 여러 측량업종을 고려한다. 중복 식별자, 공표행수 불일치, 필수열 누락, 30% 이상 감소, 기준일 후퇴는 이전 정상본을 유지한다.

충북은 '청주시 제외'라는 설명과 청주시 주소 행이 함께 존재하므로 포함범위 주의를 표시한다. 출처별 범위 밖의 업체는 미검색될 수 있다. 협회는 공식 검색 링크만 연결하며 전국 일괄 수집은 구현하지 않았다.

```sh
python -m unittest discover -s tests -p test_registry.py -v
node --test tests/registry.test.mjs
python scripts/collect_registry.py
python -m http.server 8000 --directory public
# /registry.html, /data-status.html
```

GitHub Actions는 매일 08:17 KST 예약과 수동 실행을 지원한다. 예약은 특정 시각 실행을 보장하지 않으며 실제 실행 결과를 확인해야 한다. 정상자료와 실패 메타데이터를 함께 커밋한다. 파일 원본과 해시는 실행 아티팩트에 90일 보관하며 비공개 의뢰 자료는 처리하지 않는다.

## 출시 범위 구분
저장소 반영, 테스트 통과, 수집 실행 성공, 운영 사이트 재배포는 각각 별도이다. 기존 Sites 운영 사이트의 새 화면은 배포 후 HTTP/화면 확인 전에는 완료로 기록하지 않는다. GitHub Pages에서는 공개 등록자료 화면만 정적으로 배포할 수 있으며, 인증이 필요한 기존 앱 전체를 대체하지 않는다.

등록 확인은 공인 인증·영업상태 확인·행정처분 조회·담당자 자격 확인 또는 법률자문이 아니다.
