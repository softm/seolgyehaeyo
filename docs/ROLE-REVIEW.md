# 설계해요 — 8가지 관점의 AI 설계 검토

검토일: 2026-10-22 (Asia/Seoul)  
문서 상태: 기획 합의·구현 반영 기록 · 로컬 API·예시 화면 검증 및 최종 TypeScript·production build 통과, 운영 배포·호스팅 검증 대기

## 1. 검토의 성격과 목표

이 문서는 기획자, UX, 디자이너, 설계사무소장, 변호사, 법무사, 공무원(지적과), 설계의뢰자의 **8가지 관점을 적용한 AI 제품 설계 검토**다. 실제 직군의 사람들이 회의를 개최하거나 법률·행정·설계 자문을 제공한 기록이 아니다. 아래 제안과 합의는 AI가 제품 설계를 위해 정리한 것이며, 특정 계약의 효력, 특정 업체의 적법성, 개별 사업의 허가 가능성을 판정하지 않는다.

목표는 의뢰자가 자신의 프로젝트에서 다음 일을 할 수 있게 만드는 것이다.

1. 맡길 업무와 실제 책임자를 구분한다.
2. 같은 범위로 사무소와 견적을 비교한다.
3. 계약·도면·공문·변경·지급 사실을 프로젝트에 보관한다.
4. 현재 필요한 일을 1~3개씩 확인하고 진행한다.
5. 행정 절차, 자료 인수, 미완료·보수 사항을 각각 관리한다.

**현재 구현 범위:** 개인 전용 프로젝트, 서버 D1 DB의 프로젝트·이력 저장, R2 바인딩을 통한 실파일 저장 경로를 구현했다. localhost API에서 저장·재조회·원본 다운로드·계정 간 격리·삭제를 확인했다. 이는 배포 후 실제 로그인과 운영 저장소의 동작까지 확인했다는 뜻은 아니다. 문서의 외부 AI 전송 기능은 없으며, 초대·전자서명·실제 결제·자동 자격 검증은 미구현이다. 검증 환경과 남은 확인은 [TESTING.md](TESTING.md)에 기록한다.

## 2. 1차 제안 — 역할별 관점

아래 내용은 각 관점으로 구성한 제안이며 실제 인물의 발언을 재현한 것이 아니다.

| 관점 | 우선 해결할 문제 | 1차 제안 | 피해야 할 결과 |
|---|---|---|---|
| 기획자 | 정보는 많지만 다음 행동이 모호함 | 프로젝트를 중심으로 후보 비교·계약 범위·서류·변경·지급·인수를 연결하고, 현재 할 일을 제시 | 정보 링크만 모으거나 구현되지 않은 서비스를 완성 기능처럼 표시 |
| UX | 시작부터 자료를 많이 요구하면 진입이 어려움 | 시작 필드는 3개로 제한하고 나중에 추가 허용, 현재 단계 수동 선택, 지금 할 일 1~3개 | 모든 자료를 처음부터 강제하거나 미입력을 실패로 처리 |
| 디자이너 | 완료·승인·미확인의 의미가 색상만으로 혼동됨 | 출처·상태·날짜를 글자로 표시하고, 빈 상태에 한 가지 다음 행동 제공 | 초록색 하나로 공식 확인·사용자 기록·법적 완료를 혼합 |
| 설계사무소장 | 설계·감리·토목·준공 지원 범위가 불분명함 | 포함·별도·제외 범위, 납품도서, 담당자, 질의·변경 회신을 연결 | 설계계약 하나에 모든 업무가 포함된다는 전제 |
| 변호사 관점 | 앱 버튼이 계약 합의·해지·지급 거절 권한으로 오인됨 | 사실 기록과 법적 판단을 구분하고, 변경·정산·이견의 근거를 보관 | 사기 판정, 계약 유효 판정, 자동 해지·환불 판정 |
| 법무사 관점 | 문서의 당사자·버전·인도 관계가 추적되지 않음 | 계약 상대·서명자·문서 버전·자료 인계 목록을 기록하고 필요한 개인정보만 취급 | 서명 이미지나 체크만으로 당사자·권한·법적 효력을 확정 |
| 공무원(지적과) 관점 | 측량·토지 관련 업무와 건축 절차를 한 가지 준공으로 묶음 | 지적측량과 일반 현황측량을 구분하고, 허가·협의·준공별 담당기관과 결과문서 관리 | 지도 선을 공식 경계로 판단하거나 의제 처리를 자동 추정 |
| 설계의뢰자 | 나중에 다시 들어오면 자료·진행상태를 찾기 어려움 | 저장 결과를 확인하고 재접속 시 복구, 쉬운 질문, 원본 파일 다시 열기, 누가 무엇을 할지 표시 | 임시 화면이나 예시를 실제 저장된 내 프로젝트로 오인 |

| 지급 통제와 계약 의무 | 성과물을 받고 지급하고 싶음 / 기한이 지난 지급 의무와 감리비 법정 사항 | 자료 미등록만으로 지급 거절을 권하거나 잔금을 모두 준공 이후로 설정 | 업무별 약정 지급표와 실제 지급 사실 기록, 감리비 별도 안내 |
| 준공의 단순한 표현과 여러 완료 조건 | 한 번에 끝났는지 알고 싶음 / 행정·도서·보수·정산은 다름 | 사용승인을 모든 계약 의무의 완료로 취급 | 행정 처리·도서 인수·보수 사항을 독립 상태로 관리 |
| 자료 보존과 개인정보 보호 | 원본·이력·증거 보존 / 목적에 필요한 최소 정보와 접근 통제 | 공개 파일 URL, 불필요한 주민번호, 외부 AI 전송, 무기한 보관 | 개인 전용 접근, 필요한 사본, 보관·삭제 정책, 외부 AI 전송 제외 |
| 처음 쓰는 화면의 이해와 실제 데이터 | 예시가 있으면 이해하기 쉬움 / 내 기록과 혼동 가능 | 예시 비용·자격·문서가 실제 확인 결과처럼 보임 | 예시는 별도 안내와 표시, 사용자 데이터와 저장 공간 분리 |
| 빠른 기능 확대와 검증 가능한 구현 | 초대·전자서명·결제까지 연결하고 싶음 / 현재 구현 범위 제한 | 동작하지 않는 버튼이나 성공한 것처럼 보이는 상태 | 미구현 기능은 제외하거나 명확히 미구현 표시 |

## 4. 2차 조정

### UX 제안에 대한 법률 관점의 조정

- 시작 필드 3개, 나중에 추가, 현재 단계 수동 선택, 지금 할 일 1~3개에 동의한다.
- 다만 **사용자가 고른 현재 단계와 법정 절차의 완료 여부는 별도 데이터**로 다룬다. 단계를 사용승인 준비로 옮겼다고 허가·착공·감리 절차가 완료되는 것은 아니다.
- “확인했어요”는 사용자 자신의 확인 기록이다. 상대방의 합의, 서명, 행정청의 승인으로 자동 바꾸지 않는다.
- 항목별 작성자·기록 시각·관련 자료를 남기고, 확인하지 않은 항목에는 “미확인”이나 “아직 정하지 않음”을 허용한다.
- 예시 자료에는 예시라는 표시를 유지하며, 예시에서 선택한 단계·금액·첨부파일을 실제 프로젝트의 완료 사실로 복사하지 않는다.

### 설계·지적 관점과의 조정

- 단일 안전점수 대신 **유사 경험, 포함 범위, 연락·보고 방식, 미확인 사항**을 비교한다.
- 이름 검색 결과가 없다는 이유만으로 무자격이라고 표시하지 않는다. 업체 제출자료·사용자 입력·공식 확인 자료를 구분한다.
- 건축설계·토목·측량·감리·시공의 담당자와 계약 포함 여부를 각각 기록한다.
- 건축물 사용승인, 개발행위 준공, 관련 절차의 의제·협의는 해당 사업의 자료로 확인한다. 관할기관의 판단을 앱이 대신하지 않는다.
- 최종 화면에서도 **행정 처리, 최종도서 인수, 미완료·보수**를 구분하고, 잔여 항목의 담당자와 기한을 남긴다.

### 개인정보·문서 관점과의 조정

- 개인 전용 프로젝트를 기본으로 한다. 초대·공동 접근은 현재 구현 대상이 아니다.
- 주민등록번호와 신분증 전체 사본을 기본 입력으로 요구하지 않는다. 불필요한 번호가 포함된 문서는 가린 사본 사용을 안내한다.
- 업로드한 파일의 실제 바이트를 R2에 보관하고, 메타데이터만 저장한 상태를 파일 저장 완료로 표시하지 않는 것을 구현 목표로 한다.
- 외부 AI 분석 전송을 하지 않는다. 일반 문서 저장과 향후 AI 분석은 별도의 기능·권한 설계가 필요하다.
- 실제 저장·업로드 성공 여부, 실패·재시도, 삭제 결과가 화면 상태와 일치하도록 검증한다.

## 5. 최종 합의 8개

| 번호 | 합의 | 화면·데이터 설계에 반영할 원칙 |
|---|---|---|
| 1 | 시작을 가볍게 한다 | 3개 시작 필드, 나중에 추가, 현재 단계 수동 선택, 현재 할 일 1~3개 |
| 2 | 판단 근거를 보여준다 | 점수 대신 경험·범위·연락·미확인 사항, 출처·확인일 표시 |
| 3 | 업무와 책임을 분리한다 | 건축·토목·측량·감리·시공 및 사용승인 지원의 포함·별도·제외와 담당자 |
| 4 | 사용자의 사실 기록과 법적 판단을 구분한다 | 확인·합의자료 등록·공식 문서 등록은 서로 다른 상태, 자동 사기·계약 효력 판정 없음 |
| 5 | 변경·지급·중단은 근거와 함께 남긴다 | 변경 전후·금액·일정·관련 도면, 실제 지급 증빙, 중단 시 진행분·정산·인계 기록 |
| 6 | 완료를 세 영역으로 확인한다 | 행정 처리, 자료 인수, 미완료·보수 상태를 별도 관리하고 정산 기록 연결 |
| 7 | 개인 자료를 실제로 저장하고 복구한다 | 서버 DB와 R2 실파일, 소유자 접근 통제, 재접속 복구·파일 다시 열기 검증, 외부 AI 전송 없음 |
| 8 | 예시와 미구현 기능을 정직하게 표시한다 | 예시 데이터 별도 표시·분리, 초대·전자서명·실제 결제·자동 자격 검증을 완료 기능으로 제시하지 않음 |

## 6. 구현 반영 체크리스트

**체크 표시는 명시한 범위의 코드 반영 또는 검증을 뜻한다. 운영 서비스 전체의 검증 완료 표시는 아니다.** 아래에서 `폼 검증`은 편집폼의 입력·저장 처리 검사, `로컬 API`는 localhost 프리뷰의 HTTP 통합 검사, `브라우저 QA`는 실제 브라우저에서 확인한 비로그인·읽기 전용 예시 화면을 뜻한다. 실제 로그인 사용자의 저장 UI와 배포 환경은 별도 미확인으로 남긴다.
