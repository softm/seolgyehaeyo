# 개발 순서와 완료 기준

- [x] 서비스 목적과 사용자 중심 원칙 작성
- [x] 제품 기획과 개발 순서 작성

## 1. 첫 사용자 흐름

- [ ] 홈에서 현재 상황을 선택한다.
- [ ] 선택한 상황에 맞는 할 일 1~3개와 질문을 보여준다.
- [ ] 공식 확인 경로를 대상·목적과 함께 제공한다.
- [ ] 모바일·키보드·글자 확대 환경에서 핵심 흐름을 검증한다.

완료 기준: 전문지식이 없는 사용자가 현재 상황을 고르고 다음에 누구에게 무엇을 물어볼지 이해할 수 있다.

## 2. 사무소·견적 비교

- [ ] 사무소 후보와 실제 담당자·업무 범위를 기록한다.
- [ ] 견적을 포함·별도·미정·제외 항목으로 구분한다.
- [ ] 같은 범위로 비교할 수 없는 항목을 설명한다.
- [ ] 미정 금액을 0원으로 합산하지 않는다.
- [ ] 정보 출처와 확인 날짜를 기록한다.

완료 기준: 사용자가 최초 견적 총액만 보지 않고 추가 확인할 비용과 업무를 찾을 수 있다.

## 3. 계정·프로젝트·파일 보관

- [ ] 운영 환경과 서버 저장 구조를 결정한다.
- [ ] 프로젝트별 접근 권한을 적용한다.
- [ ] 원본 파일과 버전을 보관한다.
- [ ] 저장 중·완료·실패를 실제 처리 결과에 맞춰 표시한다.
- [ ] 재로그인·다른 기기에서 프로젝트와 파일을 복구한다.
- [ ] 비인가 계정이 타인의 프로젝트와 파일을 읽을 수 없는지 검증한다.
- [ ] 자료 내보내기를 구현한다.

완료 기준: 저장 성공으로 표시한 자료가 계정에 남고, 허용된 사용자만 다시 열 수 있다.

## 4. 진행·변경·마무리

- [ ] 단계별 담당자·기한·기다리는 이유·근거 자료를 기록한다.
- [ ] 변경 내용과 비용·일정 영향, 합의 상태를 구분한다.
- [ ] 공식 완료 절차와 실제 인수·보수·자료 인계를 구분한다.
- [ ] 남은 항목에 담당자와 다음 확인일을 지정한다.

완료 기준: 사용자가 현재 상태와 남은 작업을 확인하고, 변경의 근거와 약속을 찾아볼 수 있다.
