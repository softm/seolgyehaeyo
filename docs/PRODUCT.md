# 설계해요 제품 기획 · v0.1

문서 갱신일: 2026-10-22

이 문서는 기존 제품 방향을 유지하면서 **현재 소스에 구현한 기능과 후속 검토 대상을 구분**합니다. 운영 배포와 종합 검증의 완료 여부는 [ROADMAP](ROADMAP.md)에 별도로 기록합니다.

## 서비스 정의

설계해요는 설계사무소를 잘 고르고, 맡긴 업무가 잘 진행되고 마무리되도록 **의뢰자의 확인·소통·의사결정을 보조하는 서비스**입니다.

의뢰자는 자신의 프로젝트를 기준으로 후보를 검토하고, 견적·계약 내용을 정리하고, 질문·변경·추가 비용을 기록하고, 행정 결과와 최종 자료를 챙깁니다. 설계·법정 감리·측량·시공과 관청의 판단은 실제 담당자가 수행합니다. 앱은 업체의 품질이나 허가·준공 결과를 보장하지 않습니다.

모든 안내는 다음 질문에 답하도록 구성합니다.

1. 지금 무엇을 확인해야 하나요?
2. 누구에게 무엇을 물어보거나 요청해야 하나요?
3. 다음 행동을 결정하려면 어떤 자료가 필요한가요?

### 명명 계열

| 한눈 · hannun | 해요 · haeyo |
|---|---|
| 정보를 찾고 이해하고 비교하기 | 일을 선택하고 진행하고 끝내기 |
| 무엇이 있고 어떻게 다른가요? | 지금 무엇을 해야 하나요? |

설계해요는 **해요 계열** 서비스입니다. [공통 명명 기준](https://github.com/softm/softm.github.io/blob/main/projects/development/SERVICE-NAMING-STANDARD.md)과 [브랜드 결정 기록](BRAND.md)을 유지합니다.

## 1. 시작과 프로젝트 흐름

처음 입력하는 필드는 프로젝트 이름, 맡길 일, 현재 단계 세 가지입니다. 맡길 일은 주택, 상가 등 건축, 토지·토목, 측량, 복합 업무, 아직 모름 중에서 고릅니다. 지역·주소·예산·목표일은 선택 입력입니다.

| 단계 | 사용자가 확인할 일의 예 |
|---|---|
| 준비 | 하고 싶은 일과 예산 조건, 필요한 측량 목적 정리 |
| 사무소 선정 | 책임 담당자·등록자료·유사 경험·같은 범위의 견적 비교 |
| 계약 | 맡길 업무·결과물·지급·변경·자료 인계 조건 정리 |
| 설계 | 검토한 도면의 버전과 요구사항, 다음 회신 기록 |
| 인허가 | 필요한 절차와 접수·보완·결과문서 구분 |
| 공사·변경 | 설계·감리·시공 담당, 변경비·기간·합의 자료 확인 |
| 마무리 | 행정 결과, 자료 인수·정산, 남은 작업·보수 확인 |

중간 단계에서 시작할 수 있고 앞 단계의 미완료 항목이 다음 단계 선택을 막지 않습니다. 현재 단계는 사용자가 선택한 위치입니다. 단계를 바꿔도 다른 할 일, 상대방의 동의, 관청의 절차가 자동 완료되지 않습니다.

프로젝트 종류를 바꿀 때도 기존 기록을 보존합니다. 체크리스트를 통째로 다시 만들지 않으며, 새 업무에 필요한 할 일은 사용자가 추가·수정하도록 안내합니다.

## 3. 사무소와 등록자료

사무소 기록은 이름만으로 시작할 수 있습니다. 책임 담당자, 유사 경험, 맡는 범위, 연락 방식, 등록자료 번호·메모, 출처 URL, 확인일은 상담하면서 보완합니다.

등록자료 상태는 “확인 전 / 자료 요청 / 내가 확인한 자료 기록”입니다. “확인 기록 있음”에는 사용자가 적은 확인 내용과 날짜가 필요합니다. 이는 앱이나 행정기관이 자격을 검증했다는 뜻이 아닙니다.

대한건축사협회, 건축사등록원 등 공식 확인 경로를 제공합니다. 이름 검색 결과가 없다는 이유만으로 무등록이라고 표시하지 않습니다. 건축사 자격·사무소 개설, 일반측량·지적측량, 감리·시공의 담당 범위를 혼동하지 않도록 설명합니다.

선택한 후보 표시는 사용자의 비교 기록입니다. 계약 체결이나 상대방의 수락을 자동 생성하지 않습니다. 공개 업체 검색 데이터베이스, 추천 순위, 후기 수집, 자동 자격 조회는 v0.1에 없습니다.

## 4. 견적·계약·지급

### 견적

설계, 인허가, 측량, 감리, 현장방문, 추가변경의 여섯 범위를 같은 질문으로 비교합니다. 항목별 상태는 포함·별도·미정·제외입니다. 견적 총액, 부가세 포함·별도·미정, 별도 항목 금액과 원본 메모를 기록합니다.

- 빈 금액은 미정이며 0원과 구분합니다.
- 별도 항목의 금액이 없으면 “별도·아직 미정”으로 표시합니다.
- 입력한 견적 총액에 항목 금액을 자동 합산하지 않습니다.
- 범위나 부가세가 다르면 최초 총액만으로 총지출을 비교하기 어렵다고 안내합니다.
- 예시 가격을 시장 평균이나 적정 설계비로 제시하지 않습니다.

### 계약

계약 상대, 받은 자료의 상태, 계약서 금액·서명일, 포함 업무, 결과물, 지급 조건, 변경·추가비 기준, 중단·자료 인계 조건을 기록합니다. 계약 상태는 초안·받음·서명본 기록·변경계약 기록으로 구분합니다.

계약 내용을 입력하거나 서명본 상태를 선택하는 동작은 전자서명이나 전자계약 체결이 아닙니다. 건축·토목·측량·감리·시공 및 사용승인 지원의 실제 계약 상대와 범위를 구분하도록 안내합니다.

### 지급

지급 예정, 청구 받음, 자료 확인 중, 지급 사실 기록, 이견 있음을 구분합니다. 금액·약정일·실제 지급일과 이체 증빙 메모를 적을 수 있습니다.

화면의 지급액 합계는 **금액을 입력한 지급 사실 기록의 합계**입니다. 지급했지만 금액을 적지 않은 항목은 건수를 별도로 표시합니다. 은행 조회·결제·송금은 실행하지 않습니다. 감리비를 포함한 업무별 약정과 법정 확인 절차는 가이드의 공식 자료로 안내합니다.

## 5. 할 일·질문·변경의 의미

| 할 일 상태 | 의미와 입력 원칙 |
|---|---|
| 확인 전 | 아직 확인하지 않았거나 시작 전 |
| 답변 기다리는 중 | 담당자와 다음 확인일을 남길 수 있음 |
| 접수·제출 기록 | 접수번호·제출 자료를 기록하며 승인과 구분 |
| 보완 중 | 보완 내용과 담당·기한을 기록 |
| 자료·내용 확인 기록 | 실제 확인한 자료나 내용을 남김 |
| 해당 없음 | 이 사업에 해당하지 않는 이유를 남김 |

자료·내용 확인과 해당 없음의 근거가 비어 있으면 저장하지 않도록 검증합니다. 색뿐 아니라 상태 이름과 설명을 표시합니다. 파일명·받은 자료·답변·버전·접수번호는 텍스트로 기록하고 원본은 자료함에 별도로 보관합니다. 파일 등록과 개별 할 일·질문·변경의 자동 연결은 제공하지 않습니다.

질문·메모에는 받은 답변, 연락 상대, 다음 확인일, 추가 확인 여부를 기록합니다. 복사한 질문은 사용자가 직접 전달합니다. 앱에서 업체에 메시지를 발송하지 않습니다.

변경 기록에는 변경 전후, 이유, 금액 증감, 기간 증감, 논의 상대, 합의자료 날짜·근거가 들어갑니다. 미정, 0, 증액·감액을 구분합니다. 합의자료를 확인한 상태에는 근거가 필요하며, 사용자 체크가 상대방의 동의를 대신하지 않습니다.

## 6. 마무리

마무리는 세 영역을 독립적으로 확인합니다.

1. **행정 결과:** 해당 사업에 필요한 사용승인·준공 등 결과문서.
2. **자료 인수·정산:** 약속한 최종도면·서류·파일과 정산 확인.
3. **남은 작업·보수:** 남은 내용, 담당자와 다음 확인일.

추가 일반 확인 항목도 함께 보여 줍니다. 사용승인서를 받았다는 기록만으로 자료 인수·하자보수·대금 정산을 완료하지 않습니다. 관청 처리 기간과 업체가 약속한 회신·작업 일정도 같은 것으로 취급하지 않습니다.

## 7. 서버 저장·파일·권한

현재 기술 구성은 Vinext·React·TypeScript, Cloudflare Workers, D1, R2, Sites의 ChatGPT 인증입니다. 프로젝트 소유자의 식별자에 연결해 프로젝트·이력을 D1에 저장하고, 업로드 파일의 실제 내용은 R2에 보관합니다.

Site의 기본 공개 범위는 owner-private입니다. 앱에서도 목록·조회·수정·업로드·다운로드·내보내기·삭제마다 소유자를 확인합니다. 프로젝트나 파일 ID를 알고 있다는 사실만으로 접근 권한이 생기지 않습니다. 공동 사용자·초대 기능은 없습니다.

### 파일

- 파일당 최대 20MiB이며 한 번에 하나씩 올립니다.
- PDF, 주요 사진 형식, DOCX, XLSX, DWG, DXF, UTF-8 TXT를 지원합니다.
- 종류는 계약·견적 / 등록·자격 / 설계도서 / 행정 결과 / 현장·보수 / 기타입니다.
- 파일명·크기·종류·버전 메모와 보관 시각을 기록합니다.
- 새 버전을 올려도 기존 파일을 덮어쓰지 않습니다.
- 서버가 크기·허용 확장자·내용 형식을 검사합니다. 이 검사는 문서의 진위나 자격·승인 여부를 확인하는 기능이 아닙니다.
- 주민등록번호 등 불필요한 정보는 가린 사본을 사용하도록 안내합니다. 원본인지 가린 사본인지 버전 메모로 구분할 수 있습니다.
- 외부 AI 문서 분석 전송은 구현하지 않았습니다.

### 저장과 충돌

서버 저장 응답 후에 저장 성공을 표시합니다. 폼 저장 실패 시 입력 내용은 열린 폼에 남습니다. 다른 화면에서 같은 프로젝트가 바뀌면 버전을 검사해 오래된 내용의 덮어쓰기를 막고, 입력을 복사한 뒤 최신 기록과 대조하도록 안내합니다. 이는 자동 병합이나 브라우저 종료 후 초안 복구 기능은 아닙니다.

계정의 서버 기록을 다시 불러오는 API를 구현했습니다. 실제 재로그인·다른 기기·운영 환경에서의 복구 검증 결과는 출시 검증 기록으로 관리합니다.

### 내보내기·보관·삭제

JSON 내보내기는 프로젝트 입력, 수정 이력, 파일 목록과 다운로드 경로를 포함합니다. **파일 바이트는 포함하지 않으며, 원본은 로그인한 상태에서 별도로 내려받아야 합니다.** JSON 가져오기와 전체 원본 ZIP 다운로드는 없습니다.

보관은 진행 목록에서 분리하는 동작입니다. 삭제나 공식 업무 완료가 아닙니다. 영구 삭제는 프로젝트 이름을 다시 입력해 실행하며, 앱이 관리하는 프로젝트·이력·첨부 원본을 함께 삭제합니다. 중간 실패 시 삭제 재시도를 안내합니다. 삭제한 프로젝트를 앱에서 복구하는 기능은 없습니다. 플랫폼 운영 로그와 백업의 세부 보존 정책을 앱의 삭제 기능과 혼동하지 않습니다.

## 8. 접근성과 쉬운 사용

짧은 기본 입력과 펼쳐 보는 추가 정보, 텍스트가 있는 상태 표시, 입력 레이블, 오류 설명, 키보드로 여는 대화상자, 작은 화면용 메뉴를 구현합니다. 사용자가 직접 법규나 구조안전을 판정하도록 요구하지 않고 담당 전문가에게 물어볼 질문을 제공합니다.

모바일·키보드·글자 확대·대비·화면 낭독과 실제 사용자 이해도는 별도 검증 항목입니다. 기능 구현만으로 접근성 검증을 완료했다고 표시하지 않습니다.

## 9. 후속 검토 대상

초대·공동 편집, 공공자료 자동 조회, OCR·AI 분석, 자동 알림, 전자서명, 실제 결제·송금, 지도 기반 업체 탐색, JSON 가져오기, 개별 첨부 삭제와 일괄 원본 내보내기는 현재 제공하지 않습니다.

공공 조회를 도입하기 전에는 자료 범위·이용 조건·기준일·동명이인·조회 실패를 확인해야 합니다. OCR·AI를 도입할 때는 원문 위치, 사용자 수정·검토, 문서 처리 범위와 동의를 설계해야 합니다. 이 항목들은 출시 약속이나 구현 완료 표시가 아닙니다.

공식 확인 경로와 상세 실무 설명은 [사용자 가이드](user-guide.md)를, AI 역할 관점의 논의는 [ROLE-REVIEW](ROLE-REVIEW.md)를 참고합니다.
