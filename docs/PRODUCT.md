# 설계해요 제품 기획

## 서비스 정의

설계해요는 설계사무소를 잘 고르고, 의뢰한 업무가 잘 진행되고 마무리되도록 **의뢰자의 확인·소통·의사결정을 보조하는 서비스**입니다.

사용자는 자신의 프로젝트를 기준으로 업체를 검토하고, 견적과 계약 내용을 이해하며, 진행 중 생기는 질문·변경·추가 비용을 확인하고, 준공과 업무 완료에 필요한 결과물을 챙깁니다.

모든 안내는 다음 세 가지 질문에 답하도록 구성합니다.

1. 지금 무엇을 확인해야 하나요?
2. 누구에게 무엇을 물어보거나 요청해야 하나요?
3. 다음 단계로 넘어가려면 무엇이 준비되어야 하나요?

### 의뢰자에게 제공할 도움

| 시점 | 사용자가 하려는 일 | 서비스의 보조 |
|---|---|---|
| 선정 전 | 내 일에 맞는 사무소 고르기 | 요구사항 정리, 유사 경험·담당자·등록 확인, 동일 조건 비교 |
| 계약 전 | 무엇을 얼마에 언제까지 맡기는지 정하기 | 포함·별도·미정 비용, 업무 범위·결과물·지급·변경 조건 확인 |
| 수행 중 | 맡긴 일이 약속대로 진행되는지 이해하기 | 현재 단계·담당자·기한·대기 이유·받은 자료 확인 |
| 변경 시 | 비용과 일정 영향을 알고 결정하기 | 변경 전후 내용, 추가 금액, 기간, 합의와 검토 기록 |
| 마무리 | 준공과 업무 완료에 필요한 것 챙기기 | 공식 완료자료, 최종도면, 인수·보수·정산 확인 |

설계와 법정 감리 등 전문 업무는 해당 담당자가 수행하며, 앱은 의뢰자가 설명을 이해하고 확인·결정·기록하도록 돕습니다. 업무 품질이나 허가·준공 결과를 보장하는 표현은 사용하지 않습니다.

## 명명 계열

- **한눈(hannun)**: 정보를 탐색하고 이해하며 비교하는 데 중심을 둡니다.
- **해요(haeyo)**: 사용자의 선택·실행·진행·완료를 보조하는 데 중심을 둡니다.

설계해요는 의뢰자가 설계 업무를 맡기고 완료하는 과정을 보조하는 **해요 계열** 서비스입니다. [공통 명명 기준](https://github.com/softm/softm.github.io/blob/main/projects/development/SERVICE-NAMING-STANDARD.md)을 적용합니다.

## 1. 제품이 해결할 문제

처음 설계를 맡기는 사람은 전문자격의 명칭이나 행정절차보다 “내 일을 맡길 수 있는 곳인지, 총지출이 얼마인지, 언제 무엇을 받는지”를 먼저 알고 싶어 합니다.

설계해요은 이 질문에서 시작해 후보 비교, 계약, 설계·공사 진행, 최종 자료 인수를 이어주는 웹앱을 목표로 합니다. 건축설계와 토목·측량이 함께 필요한 경우에는 실제 수행자와 업무 범위를 구분하도록 안내합니다.

## 2. 시작 화면

첫 화면의 질문은 **“지금 어떤 상황인가요?”**입니다.

| 선택 | 처음 보여줄 행동 |
|---|---|
| 설계사무소를 알아보고 있어요 | 하고 싶은 일 정리 → 후보와 상담 → 같은 기준으로 비교 |
| 견적을 받았어요 | 견적 항목 확인 → 포함·별도·미정 구분 → 질문 만들기 |
| 계약하려고 해요 | 담당자·업무 범위·결과물·금액·일정 확인 |
| 이미 맡겼는데 걱정돼요 | 마지막 결과물 확인 → 기다리는 작업·담당자·기한 정리 |
| 공사가 거의 끝났어요 | 공식 완료 절차 → 남은 보수 → 받을 자료 확인 |

최초 입력은 하고 싶은 일, 지역 또는 주소, 현재 상황 정도로 제한합니다. 예산·면적·목표일은 나중에 보완할 수 있으며 “아직 모르겠어요”를 허용합니다. 전국 단위 탐색과 실제 사업 검토에 필요한 상세 주소 입력 시점을 구분합니다.

## 3. 핵심 화면과 제공 정보

| 화면 | 먼저 보여줄 정보 |
|---|---|
| 홈 | 현재 상황, 지금 할 일 1~3개, 이어서 할 프로젝트 |
| 사무소 비교 | 맡는 일, 유사 사례, 실제 담당자, 연락·상담 방법, 업무 범위 |
| 기본 등록 확인 | 무엇을 어느 기관·자료로 언제 확인했는지, 남은 질문 |
| 견적 비교 | 같은 업무 범위의 금액, 포함·별도·미정 비용, 부가세 기준 |
| 계약 준비 | 약속할 결과물·일정·지급·변경·중단·인계 항목 |
| 진행 현황 | 지금 단계, 기다리는 이유, 담당자, 다음 확인일, 근거 자료 |
| 변경 기록 | 바뀌는 내용, 금액·일정 영향, 검토·합의 상태 |
| 마무리 | 공식 완료자료, 최종도면, 미완료·보수, 인수·정산 |
| 자료함 | 원본 파일, 버전, 연결된 단계·질문·결정사항 |

각 확인 항목에는 사용자가 그대로 보낼 수 있는 질문을 제공합니다. 예: “견적 금액 외에 제가 따로 내야 할 돈이 있나요?”

등록 확인만으로 서비스 품질이나 사기 위험을 보증하지 않습니다. 검색되지 않았다는 사실만으로 무등록이라고 표시하지 않습니다.

## 4. 비교와 상태 표시

### 비용

- 포함: 해당 견적에 포함된 업무와 금액.
- 별도: 추가 지급이 필요한 항목. 금액이 없으면 미정 표시.
- 미정: 필요 여부, 포함 여부 또는 금액을 아직 확인하지 못한 항목.
- 제외: 맡지 않는 업무. 사용자가 별도 준비할 필요가 있는지 설명.

미정 금액은 0원으로 계산하지 않습니다. 총액을 보여줄 때 확인된 금액과 아직 빠진 항목을 함께 표시합니다. 같은 범위로 비교할 수 없는 견적은 그 이유를 안내합니다.

### 확인 상태

“확인했어요 / 물어볼 것이 있어요 / 답변을 기다려요 / 전문가 확인이 필요해요”처럼 이유와 다음 행동을 연결합니다. 상태에는 글자와 아이콘을 사용해 색상에만 의존하지 않습니다.

법규·구조안전 같은 전문 판단은 사용자가 직접 판정하도록 요구하지 않습니다. 담당 전문가에게 확인할 내용과 받을 자료를 안내합니다.

### 정보 출처

| 출처 | 함께 기록할 내용 |
|---|---|
| 공식 자료 | 기관·문서·기준일·조회일·확인 범위 |
| 업체 설명 | 제공 업체·제공일·근거 문서·미확인 사항 |
| 사용자 입력 | 입력자·입력일·확인 필요 사항 |
| AI 추출 | 원본 파일·원문 위치·사용자 검토 상태 |

원자료 기준일, 수집 시각, 마지막 검증 시각은 구분합니다. 실제 API의 제공 범위·갱신 주기·이용 조건을 확인하기 전에는 전국 실시간 자동 확인을 약속하지 않습니다.

## 5. 접근성 및 이용 편의

- 휴대전화 화면에서 한 번에 한 결정을 할 수 있도록 구성합니다.
- 전문용어는 쉬운 말로 먼저 설명하고 필요한 경우 상세 설명을 펼칩니다.
- 버튼 이름을 “확인” 대신 “견적에 빠진 비용 확인하기”처럼 행동이 드러나게 씁니다.
- 키보드 조작, 보이는 포커스, 입력 레이블, 오류 설명을 지원합니다.
- 본문과 버튼의 충분한 대비, 글자 확대, 작은 화면 줄바꿈을 검증합니다.
- 사진·파일 입력과 직접 입력을 함께 검토하고, 추출 오류를 수정할 수 있게 합니다.
- 공개 가이드와 확인 경로는 가입 없이 접근하는 방향을 우선 검토합니다.
- 정보를 모두 입력하지 않아도 진행할 수 있게 하고, 나중에 보완할 항목을 남깁니다.
- 전화와 공식 페이지 링크에는 연결 대상과 목적을 표시합니다.

## 6. 프로젝트와 파일 저장

개인 계약서·서명·계좌·도면·현장사진은 기본 비공개로 설계합니다. 공개 업체정보와 프로젝트 자료는 데이터와 접근 권한을 분리합니다.

저장할 대상은 프로젝트 기본정보, 업체 후보, 견적 항목, 확인 기록, 파일 원본·버전, 단계, 질문·답변, 변경·합의, 지급 기록, 완료·보수 목록입니다.

서버 저장이 실제 완료되기 전에는 “저장 완료”로 표시하지 않습니다. 다시 로그인하거나 다른 기기에서 접속해도 저장한 상태와 파일을 복구해야 합니다. 로컬 임시저장은 서버 보관을 대체하지 않습니다.

파일 업로드 실패·네트워크 끊김·중복 업로드에 대한 사용자 안내와 재시도를 설계합니다. 자료 수정은 필요한 이력을 남기고, 사용자는 자신의 자료를 내보낼 수 있어야 합니다.

## 7. 첫 출시 범위

우선 상황별 안내, 쉬운 질문, 수동 입력 기반 사무소·견적 비교, 프로젝트 보관, 단계별 할 일에 집중합니다.

공공자료 자동 수집, OCR·AI 문서 분석, 업체와의 직접 협업, 알림은 실제 제공 조건과 핵심 흐름의 동작을 검증한 후 순차 검토합니다. 기획된 기능과 실제 제공 기능은 화면·문서에서 구분합니다.

내용의 바탕과 공식 확인 경로는 [사용자 가이드](user-guide.md)를 참고합니다.
