# 설계해요 — 정식 등록업체 검증 설계

## 목적
의뢰자가 계약 전에 실제 수행업체와 책임자의 등록·업무범위·최근 확인자료를 비교할 수 있게 한다. 자동 조회 결과를 '사기 판정'으로 표시하지 않는다.

## 업종 구분
- 건축사사무소: 건축사 자격등록과 건축사사무소개설신고를 별도 확인
- 측량업체: 등록 업종과 실제 수행 업무 범위 확인. 일반측량과 지적측량을 혼동하지 않음
- 토목설계 등: 개별 업무에 필요한 등록·자격 및 실제 수행자를 확인
- 감리·시공: 별도 법정 요건 확인

## 출처 우선순위
1. 관할 행정기관의 현재 등록·처분 확인
2. 해당 법정 등록기관·공식 협회의 증명 및 조회
3. 지자체 공개 엑셀·공공데이터 파일
4. 업체 제출 서류(진위 별도 확인)

각 원본은 source_name, source_url, jurisdiction, dataset_title, dataset_date, downloaded_at, checked_at, file_hash, license_terms, original_filename, parser_version, record_count를 보관한다. 공개 파일에 포함되지 않은 값은 추측하지 않는다.

## 정기 수집
- 출처 목록은 실제 공식 URL과 공개 주기를 검증한 후 등록한다.
- 기본 점검은 매주 1회. 원본 갱신주기는 출처별로 기록한다.
- 변경 시 다운로드 → 원본 보존 → XLS/XLSX/CSV 구조 검사 → 컬럼 매핑 → 정규화 → 이전 버전 비교 → 검증 → 공개 반영.
- HTTP 실패·빈 파일·헤더 변경·중복 증가·건수 급감·파싱 오류는 기존 정상 버전을 유지하고 실패 상태를 알린다.
- GitHub Actions 등 스케줄러는 원본 다운로드가 허용된 경우에만 적용한다.
- 데이터 출처와 원본 링크, 기준일, 마지막 성공 수집 시각, 수집 주기, 수집 건수, 실패 내역을 data-status.html에 노출한다.

## 매칭
- 업체명 정규화(공백, 법인 표기, 괄호), 주소, 등록번호, 대표자 등 사용 가능한 필드로 후보 매칭.
- 등록번호 일치가 가장 강한 근거. 상호만 같은 경우 자동 확정 금지.
- 이름 변경, 이전, 동일 상호, 폐업 후 재등록, 지점·본점 관계를 별도 처리.
- 신뢰 가능한 식별자가 부족하면 '동일 업체 여부 확인 필요' 표시.
- 원본에 없는 자격·영업상태를 임의로 추론하지 않음.

## 사용자 표시
- 공식 자료에서 확인됨: 출처·기준일·확인 범위를 함께 표시
- 최근 자료 미확인: 새 자료에서 발견하지 못했으며 등록 취소로 단정하지 않음
- 자료 불일치: 상호·주소·등록번호 차이와 확인 방법 제공
- 관할기관 확인 필요: 문의처와 질문 복사 제공
- 확인 실패: 조회 오류와 마지막 정상 확인일 표시

'정식 허가', '안전한 업체', '무면허', '사기' 등 확정 문구는 자동 매칭만으로 사용하지 않는다.

## 검증 API 및 데이터 모델(구현 계약)
- GET /api/registry/sources : 출처, 갱신주기, 최근 수집상태
- GET /api/registry/search?q=&category=&region= : 공식 자료 후보 검색
- GET /api/registry/records/:id : 등록업종, 원본 근거, 데이터 기준일, 매칭 상태
- POST /api/projects/:id/registry-checks : 사용자 프로젝트에 검증 스냅샷 보관(인증 필수)
- 저장 항목: record_id, source_id, match_method, match_confidence, review_status, checked_at, raw_reference, notes

위 API는 설계 명세이며 실제 연결 여부는 별도 테스트로 확인한다.

## 수용 기준
1. 건축사와 측량업을 교차 오판하지 않는다.
2. 동명이인·동일 상호를 자동으로 동일 업체 확정하지 않는다.
3. 원본 링크·기준일·확인시각·등록 업종을 화면에 표시한다.
4. 갱신 실패 시 과거 자료를 최신이라고 표시하지 않는다.
5. 업체가 공개 명단에 없을 때 무등록이라고 단정하지 않는다.
6. 프로젝트 기록에는 확인 당시의 근거와 스냅샷이 남는다.
7. 자료 재수집 전후 추가·삭제·변경 건수를 감사 기록으로 남긴다.
